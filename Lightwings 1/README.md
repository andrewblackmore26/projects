# Lightship

A Godot twin-stick arena shooter about absorbing light, choosing a new hull and surviving five level bosses. Light is both health and progress: damage can shrink your ship, and regrowth gives you another choice.

The presentation follows the living circle-and-line references: saturated outlines, travelling rim lights, orbiting fan clusters, following tails and distinct weapon trails over dark fills. Quiet tactile audio remains. [The presentation revision](docs/VISUAL_REDESIGN.md) documents the shared style, geometry compatibility and review criteria.

This workspace implements the **v0.3** design (`docs/LIGHTSHIP_GAME_SPEC_V3.md`, with its approved-scope preamble): two geometric primitives, six tiers, five bounded levels on a Chebyshev lattice, absorb-to-unlock elements, momentum/dash handling, a frictionless death loop, and a visual-novel companion that speaks between fights. Current evidence and its limits are in [docs/VALIDATION.md](docs/VALIDATION.md); the archived v0.2 spec and its own record are [docs/LIGHTSHIP_GAME_SPEC.md](docs/LIGHTSHIP_GAME_SPEC.md) and [docs/VALIDATION_V02.md](docs/VALIDATION_V02.md).

## Modes

Three modes (`scripts/world/mode_config.gd`), one save slot each: **Campaign** (all five levels, all five elements, T1-T6), **Dev** (level select, every element unlocked from the start, a tier-set console, never cloud-synced or achievement-earning — stays in the shipped build, but the main menu only offers it outside a demo build), and **Demo** (campaign levels 1-2, Lightning and Fire only, **no tier cap** — the approved preamble's dropped-scope table). A demo save imports into a fresh campaign profile from the main menu.

## Run

Open `project.godot` in the pinned Godot 4.7.2 engine, or run:

```powershell
powershell -ExecutionPolicy Bypass -File tools/run.ps1            # campaign
powershell -ExecutionPolicy Bypass -File tools/run.ps1 -Demo      # demo build flavour
powershell -ExecutionPolicy Bypass -File tools/run.ps1 -Editor    # Godot editor
powershell -ExecutionPolicy Bypass -File tools/run.ps1 -Benchmark # rendered-frame benchmark
```

Steam is optional for local play; the local runtime, settings and saves work without an owned Steam App ID. Partner configuration is described in [scripts/platform/STEAM_SETUP.md](scripts/platform/STEAM_SETUP.md).

## Controls

| Action | Keyboard / mouse | Controller |
|---|---|---|
| Move | WASD | Left stick |
| Aim | Mouse | Right stick |
| Fire primary | Hold left mouse | Hold RT |
| **Dash** | Right mouse | Left trigger |
| Secondary 1 / 2 / 3 | Space / Shift / Q | LB / RB / X |
| Evolve | E | A |
| Map | Tab | Back / View |
| Pause | Escape | Menu / Start |

Dash carries momentum, not invulnerability — it has no i-frames. Options include rebinding, auto fire, glow, damage numbers, and a **reduced-warp** accessibility toggle that shortens/softens the node-to-node warp presentation. Evolution chooses a complete hull with its authored primary, secondaries and passives; there is no in-run component inventory. Map and evolution menus pause combat; death does not (see below).

Options are grouped into Audio, Display, Gameplay and Controls. Master, Effects, Interface and Ambience have independent volume controls and true mute. Pickup cues are off by default; enabling them limits feedback to one cue per quarter-second. Existing master-volume and ambience-enabled preferences are retained.

## Progress and world

Start at the origin in a shared neutral seed hull with 40 light, Lightning unlocked. Six tiers span T1 (100 light to reach T2) through the terminal T6 (2300-light capacity, tier-point budget 36); falling below a tier's regression floor reshapes you to the preceding hull, with reshape protection. The player roster is **101 hulls** across the five elements and six tiers (146 authored hulls total, including enemy/elite/boss variants) — every hull is built from circles and lines through a shared motion evaluator (`scripts/ships/ship_motion.gd`). Orbit guides describe motion; actual connecting lines provide every external component's path to the core.

The world is five BOUNDED levels, each a disc of Chebyshev-distance nodes (radii 6/8/9/11/12) around an origin, not an infinite map. Every node's membranes (open connections to its neighbours) are generated by a deterministic hash of the level seed and coordinate; a level's one boss always sits on its sealed outer perimeter. Absorbing an element's light for the first time unlocks it permanently (spec §8) — there are no waypoints or teleport in v0.3; the whole level's map fits on one screen (`MinimapModel`), always showing the boss's bearing and distance. A fresh seed is rolled for the world **every life** (on death, or on travelling to a different level).

Death is frictionless: no confirmation, no loading — the next life is already built by the time the 1.2-second, non-pausing "SIGNAL LOST" card appears, and any fresh key press (after a short input guard) or the auto-close dismisses it. A pace system (decay, combo, sized pickups, per-node enemy respawn) keeps camping worse than pushing outward — measured in `artifacts/acceptance_v03.json` (see `docs/VALIDATION.md`).

The demo is **campaign levels 1-2 (Lightning and Fire), with no tier cap** (approved preamble). It ends on the level-2 boss and offers to import your progress into a full campaign profile the next time you start one.

## Narrative

A visual-novel companion (`scripts/ui/dialogue_director.gd`) speaks only between fights — lines queue until the node is clear — reacting to your first evolution, first regression, each death (the story advances every reboot), each new element unlocked, the first elite, and each level's boss (a portrait and line on both encounter and defeat; the encounter line is the one exception to the between-fights rule, since a boss's own introduction has to be able to show while it is still alive). See `docs/VALIDATION.md`'s narrative section for what is tested (`tests/dialogue_coverage_test.gd`).

## Author ships

Development menus expose the Ship Workshop and Ship Atlas. Ship definitions live under `content/ships`; components live under `content/ships/abilities`. The workshop and game use the same renderer and resources. Player hulls use the reserved light-blue chassis; every hull is circles and lines only (no ellipse/ring/arc/crescent/tether primitives — see `docs/SHIP_WORKSHOP_V2.md`). Save validation enforces parent-graph, slot and tier-point budgets.

See [docs/SHIP_WORKSHOP_V2.md](docs/SHIP_WORKSHOP_V2.md) for authoring controls, the Motion tab, and the §22 JSON shape, and [docs/INTERFACES.md](docs/INTERFACES.md) for runtime contracts. An implemented preview is not evidence that a human designer has completed the authoring acceptance test.

## Saves and verification

Snapshots use schema **4**, typed payloads, checksums, atomic replacement and verified backups. Device settings remain separate. Loading a pre-v4 (schema ≤3) campaign preserves an exact `.legacy-v3` copy before migrating: unlocks reset to Lightning-only (the old list is kept, not discarded, in `legacy_history`), deaths and compatible story flags carry over. The dev save slot is excluded from Steam Cloud sync.

The presentation revision adds a separate geometry revision. Existing encounters consolidate removed pods into their retained cluster roots using saved damage, attachment and unpaid rewards; repeat saves do not heal ships or repay components. Campaign progression and custom hull files remain intact.

```powershell
powershell -ExecutionPolicy Bypass -File tools/test.ps1                    # headless suite
powershell -ExecutionPolicy Bypass -File tools/test.ps1 -GPU               # + Vulkan pixel tests
powershell -ExecutionPolicy Bypass -File tools/test.ps1 -Only <name>       # one test
powershell -ExecutionPolicy Bypass -File tools/gates.ps1 -GPU -Exports     # every gate + negative control; exits 0 only if all pass
powershell -ExecutionPolicy Bypass -File tools/godot.ps1 -Arguments '...' # one-off launches/captures, always quoted (see scripts/main.gd's argument loop)
powershell -ExecutionPolicy Bypass -File tools/run.ps1                    # play it
powershell -ExecutionPolicy Bypass -File tools/export.ps1 -Platform all   # Windows + Linux campaign export
powershell -ExecutionPolicy Bypass -File tools/export.ps1 -Demo           # + the demo flavour
powershell -ExecutionPolicy Bypass -File tools/verify_exports.ps1 -LinuxContainer  # runs the runtime checks inside each exported package; Linux needs Docker
python tools/package.py                                                   # archive + hash the four verified exports
```

Only builds and measurements explicitly recorded in [docs/VALIDATION.md](docs/VALIDATION.md) establish current verification. A headless simulation cannot establish rendered frame rate or Steam Deck performance.
