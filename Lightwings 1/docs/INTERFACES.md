# Runtime interfaces

Godot 4.7.2, typed GDScript. `scripts/data/game_tuning.gd` (`GameTuning`) owns the six-tier thresholds/capacities, elements, slot/TP budgets, the circular arena's dimensions and timing values. The v0.3 design is `docs/LIGHTSHIP_GAME_SPEC_V3.md` (with its approved-scope preamble); the archived v0.2 document is `docs/LIGHTSHIP_GAME_SPEC.md`.

## Ship model: primitives, catalog, generator, motion

A hull is built from exactly two primitive shapes on `PartDefinition`: `shape` (`"circle"` | `"line"`), `radius`, `filled`, `parent_id` (every non-`core` part attaches somewhere in a tree rooted at the part literally named `core`), `hp`. There is no ellipse/ring/arc/crescent/tether — a `filled=false` circle is what used to be a ring, a `line` is what used to be a tether. `ShipDefinition.schema_version == 3`, `GroupDefinition` (below) attaches motion to a subtree.

`ShipCatalog.get_ship(id) -> ShipDefinition` returns a duplicate resource or null. `ShipCatalog.roster(element, tier) -> Array[ShipDefinition]` returns player hulls for that element/tier. `ShipCatalog.validate(ship) -> Array[String]` hard-errors on parent-graph problems (cycles, a chain that never reaches `core`, a line ending on a line), attachment/slot/TP-budget violations, and circle/line count caps (≤128 circles, ≤512 lines, spec-driven). `ShipCatalog.cap_to_tier(ship, tier)` is the slot-capping helper (formerly `trim_to_tier`; the old `pick_enemy`/nearest-tier-fallback path was deleted outright in P5a — nothing guesses a hull at spawn time any more, see `CampaignState.sector_at`'s `enemy_hulls`/`elite_hulls`/`boss_hull` keys below).

`ShipGenerator` (`scripts/ships/ship_generator.gd`) is the roster source of truth: `roster_manifest() -> Array[Dictionary]` and `player_hull_count() -> int` (**101**, asserted by `package_validation.gd`) describe the authored library; `build_ship(element, tier, is_player, family, faction)`, `build_player`, `build_enemy_drone/sentry/chain`, `build_elite_*`, `build_boss` construct hulls by GROWTH BY ADDITION (a tier's hull is the previous tier's arrangement plus new parts around it, not a full attribute rewrite); `hull_id(faction, kind, element, tier) -> String` is the deterministic, non-searching id function the world descriptor calls directly (`"player_fire_t3_standard_a"`-shaped ids; see `ship_roster_test.gd` for the exact grammar). The full authored library is **141 hulls**: 101 player + 25 enemy + 10 elite + 5 boss.

`scripts/ships/ship_motion.gd`: `ShipRig` (built once per unique hull shape, pre-order DFS from `core`, cached content-addressed, ≤96 entries) and `ShipPose` (`local`/`scale`/`flare` packed arrays, stepped fresh every tick from `tick/60.0` — never a wall clock, so sim and render never disagree). `GroupDefinition` (`root_id, orbit_radius, orbit_speed, drift_amp, drift_freq, breathe_amp, chain_mode, reach_ring`) attaches orbiting/drifting/breathing/chained motion to a subtree; a group's subtree orbits the point where its root attaches to ITS PARENT. `.z` on a circle's per-instance data is a radius scale (0.0 hides it, matching the old `hidden_part_ids` cutoff); `.w` is the rim FLARE amount (`actor.part_flare`, decays over 0.25s from a hit, spec §16 target feedback — see `CombatFX` below).

`EvolutionRules.threshold(tier) -> int` returns `GameTuning.THRESHOLDS[tier-1]` (100/250/500/900/1500 for tiers 1-5) or -1 at the terminal tier (`GameTuning.MAX_TIER == 6`). `offers(current_element, tier, absorbed, unlocked, previous = [], seed_value = 0) -> Array[String]` returns three hull ids: first evolution ranks unlocked elements by absorption (stable `GameTuning.ELEMENTS`-order tie break) and fills any gap from the current/highest-ranked element's roster so three DISTINCT hulls are always produced (spec §8's fill rule); later evolutions rank the current element's four hulls and swap one for an alternative element that exceeds 40% of absorption since the last evolution. `all_offers(tier) -> Array[String]` is the Dev-mode "every next-tier hull of every element" policy (`ModeConfig.offer_policy() == "all_hulls"`), grouped by element in the UI behind a tab strip since 20 live `ShipPreview`s at once is not viable.

## Modes

`ModeConfig` (`scripts/world/mode_config.gd`) answers EVERY mode-dependent question — nothing outside its `ROWS` table decides what a mode means. Three rows, one per `CampaignState.mode`: `campaign` (slot `campaign`, cloud+achievements on, `max_tier` 6, `level_cap` 5, all 5 elements, starts with Lightning unlocked, `offer_policy "standard"`, console off), `dev` (slot `dev`, cloud+achievements off, every element unlocked from the start, `offer_policy "all_hulls"`, console ON — but only reachable outside a demo build), `demo` (slot `demo`, cloud+achievements off, `max_tier` 6 — **no cap**, per the approved preamble — `level_cap` 2, elements `[lightning, fire]` only, `offer_policy "standard"`, console off). `available_modes(is_demo_build) -> Array[String]` is the ONE place `OS.has_feature("demo")` is asked to decide menu contents. `selectable_levels(levels_completed) -> Array[int]` filters level-select per mode (dev sees all 5 always; campaign/demo see 1..min(level_cap, highest completed+1)).

`CampaignState.level_cap() -> int` (new this phase) is `mini(GameTuning.LEVEL_RADIUS.size(), ModeConfig.from_id(mode).level_cap())`; both `campaign_complete()` and `travel_to_level()`'s clamp go through it, so a demo profile cannot be walked to level 3 by any code path (level-select filtering AND this structural clamp).

## Campaign state (v0.3, schema 4)

`CampaignState` is a **square Chebyshev lattice** (spec §11), not the v0.2 wedge/core world. Coordinates are `Vector2i`; serialized keys are canonical `"x,y"` strings via `coord_key`/`key_coord`/`valid_key`.

**Persistent fields** (survive death): `mode`, `world_seed`, `epoch`, `deaths`, `unlocked` (elements earned by absorbing their light, spec §8), `levels_completed`, `best_ring` (Dictionary level -> best ring reached), `story_flags`, `legacy_history` (discarded pre-v4 fields, kept rather than dropped).

**Per-life fields** (reset whenever `epoch` changes — on death OR on `travel_to_level`): `level`, `current_sector`, `discovered`, `ring_reached`, `boss_down`, and the node light-pool bookkeeping (`_node_state`, private).

`level_seed()` mixes `(world_seed, epoch, level)`, so every life is a fresh, reproducible layout (spec §7 "a fresh seed every life"). `ring(coord)` is Chebyshev (`max(|x|,|y|)`); `tier_of(coord)` is `1 + ring/2` clamped to `GameTuning.MAX_TIER`; `in_bounds(coord)` is `ring(coord) <= level_radius()` (a bounded disc, `GameTuning.LEVEL_RADIUS = [6,8,9,11,12]` per level 1-5). `exits_of(coord)` and `boss_coord()` are pure functions of `level_seed()` and the coordinate. `archetype_of(coord)` returns one of `transit`/`skirmish`/`dense`/`elite_lair`/`boss`; `element_of(coord)` returns one of the level's revealed elements — a boss cell always gets the LAST element of `_revealed_elements()` (spec §8's per-level reveal), which is why one level always has exactly one boss element (see `scripts/ui/dialogue_director.gd`'s doc comment and `tests/dialogue_coverage_test.gd::_test_boss_per_level`).

### `sector_at(coord, now = 0.0) -> Dictionary` (the descriptor contract)

Pure and read-only — never mutates the profile, never populates a persistent map, and gives the same result regardless of call order. Keys:

| Key | Meaning |
|---|---|
| `coord`, `id` | The coordinate and its canonical string key |
| `in_bounds` | False beyond the level's perimeter (a sealed cell still gets a descriptor, with empty `exits`/`enemy_hulls`) |
| `ring`, `tier` | Chebyshev ring and the ring-derived difficulty tier |
| `element`, `archetype` | This node's rolled element and archetype |
| `kind` | `origin`, `boss`, or `regular` |
| `exits` | `Array[Vector2i]` of open cardinal directions (`Vector2i.UP/RIGHT/DOWN/LEFT`) |
| `encounter_seed`, `encounter_epoch` | Deterministic RNG seed for the node's own local rolls, and the profile's current epoch (combat clears its sector cache whenever this changes) |
| `pool_size`, `pool_remaining`, `resource_budget` | The node's light pool (spec §7): authored size, remaining after refill-since-last-visit, and the same remaining value combat reads as its economy budget |
| `respawn_cooldown` | `GameTuning.ENEMY_RESPAWN_COOLDOWN` (45s) — enemies respawn on this cooldown; the pool does not follow (spec §7) |
| `boss_down`, `cleared` | True only for the level's boss cell once its boss is beaten (a defeated boss never respawns; everything else always repopulates on return) |
| `enemy_hulls`, `elite_hulls` | `Array[String]` of EXACT roster hull ids to spawn, named directly by the descriptor (`ShipGenerator.hull_id`) — combat never guesses a hull from `(element, tier)` at spawn time |
| `boss_hull` | The boss's exact roster hull id, only set when `kind == "boss"` |
| `starter_pickups` | `Array[String]` of elements to drop at the origin, only set when `kind == "origin"` — always drawn from the level's own revealed prefix, never a hard-coded list |

`can_enter(from, to, light = 0)` checks cardinal adjacency, `in_bounds(to)`, and that `to - from` is actually one of `exits_of(from)` — a sealed perimeter or a missing membrane both refuse entry. `on_enter(coord)` updates `current_sector`, `discovered` and `ring_reached`.

`unlock_element(element, amount) -> bool` is the single place spec §8's "first time you absorb a light type" unlock happens; it returns true only on the call that newly unlocks it. `complete_level() -> {level_completed, revealed_element, next_level}` is idempotent: call it every time a boss dies; it only fires `level_completed` and reveals the next element the first time a given level is finished, and always updates `best_ring`. `campaign_complete()` is now mode-aware (`levels_completed.size() >= level_cap()`) — true for a demo profile the instant its level-2 boss is beaten, which is what `main.gd::_on_boss_defeated` uses to trigger the demo ending instead of the old hard-coded non-demo branch. `travel_to_level(new_level)` clamps to `level_cap()` and is also an epoch change (fresh layout, spec preamble "the short inverted warp plays on death and on level travel").

`node_pool_state(coord, now)` and `record_node_left(coord, now, remaining)` implement the light-pool refill (`GameTuning.NODE_POOL_REFILL_PER_MINUTE`), keyed by the campaign's own elapsed-seconds clock (never a wall clock, per lessons.md) so refill during time away from a node is deterministic and testable.

`on_death()` preserves everything in the persistent list, advances `epoch`, and resets the per-life fields via `_reset_life()`; it also sets `story_flags["reboot_%d" % deaths] = true` (each death's own key, so the companion's per-death line — `scripts/ui/dialogue_director.gd` — never repeats). `to_dict()` emits gameplay schema 4. `from_dict()` migrates any schema `< 4` profile (including genuine v0.2 schema-3 saves) by keeping `deaths` and whitelisted `reboot_*` story flags and resetting everything else to a fresh campaign, per the approved preamble ("unlocks reset to Lightning") — the discarded fields survive in `legacy_history`, not vanish. `import_demo(profile)` carries over compatible fields into a fresh campaign profile at level 1/origin/epoch 0 — the approved preamble's "demo progress imports into the full campaign".

## `MinimapModel` (the map screen and the corner HUD)

`MinimapModel.build(campaign, debug_hide_boss = false) -> MinimapModel`: `radius`, `cells: Array[Cell]` (`coord, in_bounds, explored, current, is_boss`), `boss_coord`, `bearing_direction` (8-way compass string), `bearing_distance` (Manhattan distance to the boss, present from tick 0 regardless of exploration — spec §11 M3), `grid_size()`, `cell_at(coord)`. Both the full map screen (`main.gd::_show_map`) and the corner minimap (`_draw_minimap`) build from this ONE model — no second source of truth. A Chebyshev disc of radius R IS the `(2R+1)x(2R+1)` square this model iterates, so the sealed perimeter is the OUTERMOST RING (`CampaignState.ring(coord) == radius`), not a set of excluded cells.

## Combat, motion feel, and the warp

`CombatWorld` owns the player's light bar, hull history, actors (per-circle HP arrays, not a single actor HP), projectiles, effects, arena collision and encounter snapshots. `setup_player(element, tier, light, legacy_stolen, position)` remains a compatibility constructor; ordinary starts use neutral/T1/40. `evolve_hull(id) -> bool` validates a threshold and next-tier hull (a +1 step only — the dev console's `tier` command goes through the separate `evolve_player(element, tier, [])` debug jump to any tier). `collect_light(amount, element)` returns the absorbed amount and updates the one bar. `start_sector(descriptor)` loads an encounter from the world descriptor's exact hull ids (no runtime picking). `set_command(ShipCommand)` supplies movement, aim, primary and three secondary actions plus dash. `snapshot()` / `restore(data)` preserve the current run through the packed per-circle codecs (`scripts/combat/combat_persistence.gd`).

Actors use world-space positions inside `CircularArena` (`center = GameTuning.ARENA_CENTER`, `radius = GameTuning.ARENA_RADIUS = 800`; there is no rectangular `ARENA_SIZE` any more). `boundary_hit` is closed-form ray/circle intersection, not a bisection search. A membrane (open connection toward a live exit) is an 80px-wide arc on the rim; every other direction is a heavy sealed wall.

Enemies are graphs, not single hitboxes: `part_hp` (per-circle HP, parallel to the ship's own circle indices), destroyed circles detach as debris (velocity kept, spin, 1s fade, drops half their light); archetypes (`scripts/combat/combat_ai.gd`) are drone/sentry/chain (fixed patterns, no reaction delay), radial/irregular (`_update_decision_driven`: 150-300ms reaction lag via one-decision-stale position/velocity, 2-5° per-gun aim error resampled per decision, retreat below half starting gun count), and boss (shielded core — `_boss_shield_active` gates ALL core damage while any `shield_generator` circle lives — and/or multi-cored via `sub_core`, never respawns).

**Warp state machine** (`enum {WARP_NONE, WARP_PUSH, WARP_ZOOM_IN, WARP_TRAVEL, WARP_ARRIVAL, WARP_ZOOM_OUT, WARP_FADE}`, `combat_world.gd`): pushing against a membrane fills `WARP_PUSH` (spring-releases at twice the fill rate if released early); crossing commits to `WARP_ZOOM_IN → WARP_TRAVEL → WARP_ARRIVAL → WARP_ZOOM_OUT` (durations 0.12/0.55/0.15/0.20s, `WARP_REDUCED_SECONDS=0.25` total when the reduced-warp accessibility option is on) with `WARP_FADE` replacing the zoom pair wholesale when reduced; `warp_locked()` is true for every phase except `NONE`/`PUSH`. `main.gd::_on_warp_committed` performs the actual sector swap SYNCHRONOUSLY the instant `warp_committed` fires (well before `WARP_TRAVEL` ends), so `combat.confirm_warp_swap()` always lands in time.

**Pace** (`_update_pace(dt)`, spec §7): light decays at `GameTuning.DECAY_RATE_PER_SECOND` (0.4%/s of tier capacity) after a 3s post-kill/absorb suppression window, floors at `DECAY_FLOOR`, can regress a tier through the same `_check_regression()` choke point damage uses; kills build a combo (`COMBO_WINDOW_SECONDS=2.5`, multiplier up to 2.5x, drains 1 count/0.25s once the window lapses) that scales the reward pool BEFORE it is split into sized pickups (`GameTuning.PICKUP_SIZES`); enemy-sourced pickups pay 3x a floating pickup of the same size (`ENEMY_DROP_MULTIPLIER`); non-boss kills respawn after `ENEMY_RESPAWN_COOLDOWN` (45s), independent of the node's own (slower) light-pool refill.

**Death** (spec §7.4/§24): `SCREEN_POLICY["death"]` (`main.gd`) does not pause the tree (`freezes_sim: true` stops only the sim) so a 1.2s auto-close timer and fresh-press dismissal can run while it is up; `_input_guard` (0.35s) ignores even a fresh press briefly so the press that caused death cannot also dismiss a card the player never saw. `_on_death` builds the next life's sector immediately (before the card even opens), so `_reboot()` (fired by the timer, a fresh press, or a fixture calling it directly) does no work of its own beyond swapping to data that already exists.

## `CombatFX` (attack/impact animation, spec §16/Appendix B)

`scripts/combat/combat_fx.gd`: a pooled SoA (`CAPACITY=512`, free-list reuse, no per-frame allocation once warmed) behind ONE choke point, `emit(template_name, at, tint, rng, extra)`. `TEMPLATES` is a dict of named beats (muzzle, impact rings A/B + fragments, collar, destruction, line_snap/chain_line/absorb/dash_ring, ricochet_kink, beam_spark, wall_flash/explosion/spawn_telegraph/damage_number). `validate_templates()` (called from `CombatWorld._ready()`) hard-errors any non-`floor_exempt` template under the spec's 0.25s floor for "one beat of a longer event"; `muzzle` (0.15s) is the one `floor_exempt` template, since it is the emitter-side beat, not the target-side hit/absorb event the floor is about. Target feedback: `actor.part_flare` (parallel to `part_hp`) is set to 1.0 by `_flare(actor, index)` and decays by `dt/0.25` every tick, read by the shader's rim AND core fragment branches (`ship_outline.gdshader`'s `flare_amount` varying); `_maybe_collar` adds a darkening ring beat above a raw-damage threshold (30.0, a stated convention). Every hand-off of a `PackedFloat32Array` between actor/pose/renderer buffers is `.duplicate()`d, never aliased — an aliased flare buffer was a real P8 bug (see `tasks/lessons.md`).

## Narrative (`scripts/ui/dialogue_director.gd`, spec §25)

A pure `RefCounted`, extracted from `main.gd` in P9. Owns `line_queue: Array[Dictionary]` and `seen_lines: Dictionary` (per-id dedupe); `main.gd` exposes both as forwarding properties (`get`/`set` delegating to the director's own live containers) so existing callers (`tests/golden_trace_test.gd`, `tests/support/make_v3_fixtures.gd`, `SaveService.save_snapshot`'s run payload) are unaffected. Two lanes on one FIFO queue: `queue(element, title, text, id)` (normal — only leaves the queue once the caller reports `combat.remaining_enemies() == 0`, spec §25 "speaks only between fights") and `queue_immediate(element, title, text, id)` (spec §25's one exception, a level boss's own ENCOUNTER line — jumps to the FRONT of the queue and is exempt from the gate; every other queued line is unaffected). `can_show_next(combat_clear)` / `pop_next(combat_clear)` are the two methods a presentation layer needs; `entry_line(root)` / `defeat_line(root)` are the static line tables, keyed by rival element (and, by construction — see `CampaignState.element_of` above — by level, since one level has exactly one boss element).

## Save and platform boundary

`SaveService.save_snapshot(profile, run, slot = "campaign") -> Error` and `load_snapshot(slot) -> {profile, run}`: the ENVELOPE (transport wrapper: format tag, encoding, SHA-256, base64 payload) is versioned separately from the GAMEPLAY schema `CampaignState.to_dict()` emits, which is now **4**. `SaveService.MAX_KNOWN_GAMEPLAY_SCHEMA` / `SchemaVersion.CURRENT` are the single literal both the migration comparison and `_validate_snapshot`'s upper bound read (a stale `schema_version > 3` cap here silently rejected every schema-4 save the first time it was tried — see `tasks/todo.md`'s P5a review). Loads try the primary, backup and temporary candidates.

Legacy (schema < 4) campaigns are copied byte-for-byte to `.legacy-v3` (or an earlier suffix for an older schema) before a migrated profile is returned; the source is untouched until an ordinary save. Compatible fields (`deaths`, whitelisted `reboot_*` story flags) survive; unlocks reset to Lightning-only per the approved preamble, with the discarded list kept in `legacy_history`, not dropped. `_mode_matches_slot` rejects a profile whose `mode` disagrees with its slot (so a stray `.bak` cannot mask a demo/campaign mismatch). The `dev` slot is never pushed through `PlatformService`'s cloud transport (spec §4).

`PlatformService` provides optional Steam Input (including the `dash` action), achievement queuing and cloud transport. Cloud inspection never replaces either save; loading a legacy local save may create its preservation archive. Conflict resolution requires a concrete local/cloud choice; cloud comparisons use the pure `preview_migration(snapshot)` transform, so choosing a legacy remote save does not reopen the same conflict. `install_snapshot(reviewed_bytes, slot)` preserves the exact reviewed transport bytes and prior local backup, then archives and migrates through `load_snapshot` before gameplay resumes. Consult `scripts/platform/STEAM_SETUP.md` for account configuration and current transport names; mocked tests do not certify a real Steam account or device.
